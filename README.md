# Flâsh Pro

Flâsh Pro သည် animated cartoon UI ပါသော chat/web app ဖြစ်သည်။ Gemini, Groq, DeepSeek, OpenAI/ChatGPT, xAI/Grok နှင့် Manus Agent ကို အသုံးပြုသူတစ်ဦးချင်းစီ၏ ကိုယ်ပိုင် API key ဖြင့် သုံးနိုင်သည်။

## ပါဝင်သောအင်္ဂါရပ်များ

- AI chat — provider တစ်ခုစီအတွက် ကိုယ်ပိုင် key၊ Enter ဖြင့်ပို့ခြင်း
- Search Friends — Private Chats inbox မှ သီးခြားစာမျက်နှာ
- Private chat နှင့် Group chat — Socket.IO real-time messaging
- Persistent login/session, Last Seen/online presence, message receipts (Sending/Sent/Delivered/Seen/Not sent), conversation pin/delete/nickname болон message reply/edit/delete/pin
- Profile photo, Account Name, lowercase Username နှင့် login ဝင်ပြီးနောက် password ပြောင်းခြင်း; user ပြောင်းထားသော public profile name/photo ကို chat များတွင် အသုံးပြုခြင်း
- Persistent AI conversation history — ယခင် chat ကိုပြန်ဖွင့်၍ ထိုစကားဝိုင်းအတိုင်း ဆက်လက်ပြောဆိုနိုင်ခြင်း
- Video downloader — ကိုယ်တိုင် host လုပ်ထားသော သို့မဟုတ် အသုံးပြုခွင့်ရ Cobalt API instance မှတစ်ဆင့်
- Music library — audio upload, playback, delete; Supabase Storage ကို ရွေးချယ်အသုံးပြုနိုင်ခြင်း; upload/download/message sending transfer progress
- Cartoon animation — nav, cards, buttons, message bubbles, modals နှင့် forms တစ်လျှောက် motion; reduced-motion preference ကို လေးစားသည်

## စတင်အသုံးပြုခြင်း

လိုအပ်ချက်: Node.js 20+ နှင့် Supabase project တစ်ခု။ Deploy မတင်မီ အောက်ပါ base tables များတည်ဆောက်ပြီး `migrations/001_persistent_chat_profile.sql` ကို Supabase SQL Editor မှာ တစ်ကြိမ် run ပါ။ Migration သည် username များကို lowercase ပြောင်းမည်။ ခွင့်ပြုထားသော ASCII username ပုံစံ (၃–၂၄ လုံး) ပြင်ပ username သို့မဟုတ် lowercase ပြောင်းပြီးနောက် ထပ်နေသော username ရှိပါက migration သည် ရပ်မည်။ အကောင့်များကို လုံခြုံစွာစစ်ပြီးမှ ကိုယ်တိုင်ပြင်ဆင်ပါ။

```bash
npm ci
cp .env.example .env
# .env ထဲရှိ Supabase နှင့် production secrets များ ဖြည့်ပါ
npm start
```

Production တွင် `SESSION_SECRET` နှင့် server-side သာသုံးရမည့် `SUPABASE_SERVICE_ROLE_KEY` ကို မှန်ကန်စွာ သတ်မှတ်ပါ။ တစ်ခုခုမရှိလျှင် server စမည်မဟုတ်ပါ။ `.env` ကို Git ထဲ မတင်ပါနှင့်။

## Supabase ပြင်ဆင်မှု

Server-side operation များအတွက် `SUPABASE_SERVICE_ROLE_KEY` ကို သတ်မှတ်ပြီး server environment ထဲမှာသာ သိမ်းပါ။ ၎င်းကို browser/frontend code ထဲ ဘယ်တော့မှ မထည့်ပါနှင့်။ Supabase မှာ အောက်ပါ column များ ပါသော table သုံးခု လိုအပ်သည်။

```sql
create table if not exists public.users (
  username text primary key,
  password text not null
);

create table if not exists public.settings (
  key text primary key,
  value text not null
);

create table if not exists public.music (
  id bigint generated by default as identity primary key,
  title text not null,
  file_url text not null,
  uploader text not null,
  folder text not null default 'General'
);
```

`settings` မှာ AI key များကို username နဲ့ provider အလိုက် သီးခြား key အဖြစ် သိမ်းသည်။ API key value များကို app က `SESSION_SECRET` မှ ဆင်းသက်လာသော AES-256-GCM key ဖြင့် encrypt လုပ်ပြီး သိမ်းသည်။ `SESSION_SECRET` ပြောင်းလိုက်လျှင် ယခင် encrypt လုပ်ထားသော API key များကို ပြန်ဖတ်မရတော့ပါ။

ယခင် app မှ shared `gemini_key` နှင့် `groq_key` rows များကို app အသစ်က မဖတ်တော့ပါ။ Backup လုပ်ပြီးနောက် database admin က မလိုအပ်တော့သော shared key rows များကို ကိုယ်တိုင်ဖယ်ရှားနိုင်သည်။

RLS ကို ဖွင့်ထားပြီး `service_role` key ကို server-side တွင်သာ အသုံးပြုပါ။ `anon` access ကို table များအတွက် အများသုံး read/write မဖွင့်ပါနှင့်။ Existing Supabase project တွင် RLS policy/schema ကွဲပြားနေပါက server log နှင့် API response တွင် database error ပြန်စစ်ပါ။

Migration က persistent session, profile, conversation/message/receipt, AI history နှင့် download-ticket tables များအပြင် profile update/download consume RPC များကိုဖန်တီးပြီး `users` နှင့် `music` columns များကို ထည့်ပေးသည်။ App အသစ်ကို migration မလုပ်မီ မတင်ပါနှင့်။ Session ကို Supabase `app_sessions` ထဲတွင် သိမ်းပြီး အသုံးပြုနေစဉ် သက်တမ်းတိုးသော one-year cookie သတ်မှတ်ထားသည်။ Logout လုပ်သည်အထိ မကြာခဏ login ပြန်မလုပ်ရပါ။ Browser/device မှ cookie ဖယ်ရှားခြင်း၊ administrator က session ကို ဖျက်ခြင်း သို့မဟုတ် တစ်နှစ် အသုံးမပြုဘဲ သက်တမ်းကုန်ခြင်းဖြစ်လျှင် ပြန်ဝင်ရန်လိုနိုင်သည်။

Username ကို စာလုံးအသေး၊ ဂဏန်း၊ `_`, `.`, `-` သင်္ကေတများဖြင့် ၃–၂၄ လုံး သတ်မှတ်ရမည်။ အသစ်သတ်မှတ်သော password သည် ၆–၈ လုံးဖြစ်ရမည်။ အကောင့်ဟောင်းများ၏ password အရှည်ကို login အတွက် လက်ခံထားပြီး login ဝင်ပြီးနောက် Profile မှ ၆–၈ လုံး password အသစ်ပြောင်းနိုင်သည်။ မေ့သွားသော password ကို app မှ ပြန်လည်သတ်မှတ်နိုင်သည့် recovery လုပ်ဆောင်ချက် မပါဝင်ပါ။

### Music storage

`SUPABASE_STORAGE_BUCKET` ကို သတ်မှတ်ထားလျှင် audio နှင့် profile photo ကို Supabase Storage ထဲတင်သည်။ Supabase Dashboard မှ bucket ကို ဖန်တီးပြီး playback အတွက် public read ကိုခွင့်ပြုပါ။ Local development တွင် bucket မသတ်မှတ်ပါက `public/uploads/` ထဲတွင် local disk သိမ်းသည်။ Production တွင် မပျောက်စေရန် bucket သတ်မှတ်ရန်လိုပြီး မသတ်မှတ်ပါက upload ကို server က ငြင်းပယ်မည်။

## AI provider များ

အသုံးပြုသူက Settings တွင် provider တစ်ခုစီ၏ ကိုယ်ပိုင် API key ကို ထည့်ရသည်။ Key များကို browser ထံ ပြန်မပို့ပါ။ API key အလုပ်မလုပ်ပါက key ကိုဖယ်ရှားပြီး မှန်ကန်သော key ဖြင့် ပြန်ထည့်ပါ။

Provider အလိုက် default model များကို environment variable ဖြင့် ပြောင်းနိုင်သည်။

- Gemini: `GEMINI_MODEL` (default `gemini-2.5-flash`)
- Groq: `GROQ_MODEL` (default `openai/gpt-oss-120b`)
- DeepSeek: `DEEPSEEK_MODEL` (default `deepseek-flash`)
- OpenAI/ChatGPT: `OPENAI_MODEL` (default `gpt-4.1-mini`)
- xAI/Grok: `XAI_MODEL` (default `grok-4.7`)
- Manus: `Manus Agent` ရွေးချယ်မှုသည် plain model inference မဟုတ်ပါ။ အသုံးပြုသူ၏ Manus API key ဖြင့် private task conversation တစ်ခုဖန်တီးပြီး ဆက်လက်အသုံးပြုသည်။

ChatGPT account subscription နဲ့ OpenAI API access/key သည် သီးခြားဖြစ်နိုင်သည်။ Provider တစ်ခုစီတွင် သက်ဆိုင်ရာ API access ရှိသော key ကို ထည့်ပါ။

## Video downloader

Cobalt ၏ official service list အရ YouTube, TikTok နှင့် Facebook ကို ပံ့ပိုးထားသော်လည်း Facebook တွင် public video များသာ ရယူနိုင်သည် ([Cobalt API README](https://github.com/imputnet/cobalt/blob/main/api/README.md))။ Hosted Cobalt instance များကို ခွင့်ပြုချက်မရှိဘဲ အခြား app မှ ခေါ်သုံးရန် မရည်ရွယ်ထားသောကြောင့် ကိုယ်ပိုင် သို့မဟုတ် ခွင့်ပြုချက်ရ instance သာ အသုံးပြုပါ ([Cobalt API docs](https://github.com/imputnet/cobalt/blob/main/docs/api.md))။ App သည် download ကို server မှ stream လုပ်ပြီး Content-Length ရရှိပါက အမှန်တကယ် download percentage ကိုပြသည်။ Server က size မပေးပါက byte ပမာဏသာပြပြီး မှန်းဆရာခိုင်နှုန်း မဖော်ပြပါ။

ကိုယ်ပိုင် သို့မဟုတ် ခွင့်ပြုချက်ရ Cobalt instance ကို `.env` ထဲတွင် သတ်မှတ်ပါ။ API key လိုအပ်သော instance ဖြစ်လျှင်သာ key သတ်မှတ်ပါ။ `COBALT_API_URL` မရှိပါက downloader က မပြင်ဆင်ရသေးကြောင်း အကြောင်းကြားမည်။

## အရေးကြီးသည့် runtime မှတ်ချက်များ

- Login session, private/group chat history, delivery receipts နှင့် AI conversations များကို Supabase တွင် အမြဲတမ်းသိမ်းသည်။ Session cookie သည် logout လုပ်ခြင်း၊ browser cookie ဖယ်ရှားခြင်း၊ administrator က session ဖျက်ခြင်း သို့မဟုတ် သက်တမ်းကုန်ခြင်းအထိ ထိန်းသိမ်းသည်။
- Profile Account Name နှင့် photo ကို server-side profile record မှ chat/friend list များတွင် ပြသသည်။ Username ပြောင်းလဲခြင်းသည် conversation ၏ user ID ကို မပြောင်းပါ။
- Music upload သည် 25 MB အထိဖြစ်ပြီး production တွင် `SUPABASE_STORAGE_BUCKET` နှင့် video download အတွက် ခွင့်ပြုထားသော `COBALT_API_URL` ကို သတ်မှတ်ပါ။ Upload/message percentages သည် browser က တကယ်ပို့ပြီးသည့် bytes ကိုသာ ပြပြီး server-side သိမ်းဆည်းနေစဉ် percentage အတုမပြဘဲ လုပ်ဆောင်နေကြောင်းပြသည်။
- `npm run check` သည် server/client JavaScript syntax ကိုစစ်သည်။ Local HTTP smoke test လည်းပြုလုပ်ထားသော်လည်း credential ပါဝင်သော provider end-to-end test များ မပါဝင်သေးပါ။
